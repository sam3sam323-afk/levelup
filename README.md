# LEVEL UP ARENA NEXUS — v1.1.0

مركز تنزيلات وإدارة وسائط محلي: واجهة سطح المكتب تعمل داخل تطبيق Electron مستقل، وتتصل بتطبيق الجوال عبر Nexus Relay على شبكة Wi‑Fi المحلية. الاقتران والتنزيلات لا تتطلب حسابًا أو وسيطًا سحابيًا.

## بناء مثبت Windows x64

متطلبات البناء: Node.js 22، pnpm 9.12.0، اتصال بالإنترنت لتنزيل الإصدارات المثبتة، وWine على Linux عند إنتاج Windows NSIS installer من Linux. في Windows لا يحتاج المطور إلى Wine.

```bash
pnpm install --frozen-lockfile
pnpm desktop:build:win
```

ينزّل أمر البناء ملفات Windows x64 المثبتة لـ`yt-dlp` و`aria2c` وFFmpeg ويتحقق من SHA-256، ثم يصدّر واجهة Expo، ويجمع Relay، ويجهز مجلد Electron runtime معزولًا عن اعتماديات Expo، ويتحقق من إصدارات المحركات وأعلام LGPL، وينشئ مثبت NSIS. الناتج في `release/win/LEVEL-UP-ARENA-NEXUS-Setup-1.1.0-x64.exe`. يضمّن المثبت المحركات والواجهة وChromium والتراخيص المطلوبة؛ لا يحتاج المستخدم النهائي إلى تثبيت المحركات منفصلة.

في البناء المتحقق منه بلغ حجم المثبت `204,486,714` بايت (`195.01 MiB`)، أي أقل بـ`165,186,504` بايت (`44.68%`) من مثبت المرحلة الثانية البالغ `369,673,218` بايت.

هذا قياس من تشغيل تغليف سابق؛ تغييرات تحسين الواجهة الحالية لم تُضمّن في Setup جديد بعد، وسيُعاد القياس بعد اعتماد مراجعة الواجهة.

يضبط Electron Builder لغتي Chromium `ar` و`en-US` فقط، ويستخدم ضغط `maximum` وNSIS 7-Zip/LZMA بدل ZIP. ملفات debug المستثناة تقتصر على خرائط المصدر وملفات PDB. لا يرفع أمر البناء GitHub Release؛ فهو ينفذ `--publish never`.

إذا كان prefix الافتراضي لـWine غير صالح على Linux، أنشئ prefix مؤقتًا يملكه المستخدم ثم مرره إلى الفحوص والبناء:

```bash
WINEARCH=win64 WINEPREFIX="$HOME/.cache/levelup-wine" wineboot --init
WINEDEBUG=-all WINEPREFIX="$HOME/.cache/levelup-wine" pnpm binaries:verify
WINEDEBUG=-all WINEPREFIX="$HOME/.cache/levelup-wine" pnpm desktop:build:win
```

يمكن التحقق من ملفات المحركات منفردة عبر `pnpm binaries:verify`. على Linux يستخدم هذا الفحص Wine لتشغيل ملفات Windows والتحقق من إصداراتها وأعلام بناء FFmpeg. يبقى تثبيت المثبت واختباره على Windows فعلي خطوة مستقلة؛ بيئة Linux لا تثبت وحدها سلوك كل إصدار Windows.

## Chromium وMedia Sniffer

يفتح زر «المتصفح» نافذة Chromium داخل التطبيق عبر `WebContentsView`، مع Session غير دائمة و`Sandbox` و`contextIsolation` وبدون Node integration أو preload في صفحات الإنترنت. شريط المتصفح يدعم الرجوع والتقدم وإعادة التحميل والبحث/العنوان، ويحتوي رابط الدعم الدائم إلى [Telegram](https://t.me/level_uparena_bot).

على Windows، يطابق `titleBarOverlay` خلفية شريط النافذة مع واجهة Nexus الداكنة بدل لون الإطار الافتراضي، مع إبقاء أزرار التحكم الأصلية قابلة للاستخدام ومساحة العنوان قابلة للسحب. تعرض صفوف التنزيل المكتمل في لوحة الكمبيوتر أزرار فتح الملف وإظهار مجلده؛ يتحقق Electron من اكتمال التنزيل ومن بقاء المسار داخل مجلد Nexus، ولا يرسل المسارات المحلية إلى Relay API أو تطبيق الهاتف.

يلتقط Media Sniffer موارد الصوت والفيديو والـmanifests من الشبكة في الصفحة النشطة، ويزيل الروابط المتكررة ويعرض لوحة الوسائط المكتشفة. يمكن فحص صيغ yt-dlp واختيار كل ارتفاع متاح، أو إرسال الفيديو بأفضل جودة، أو استخراج الصوت إلى MP3 أو M4A. الخيارات الفعلية تعتمد على المصدر وبياناته؛ لا يتجاوز التطبيق DRM أو تسجيل الدخول أو قيود الوصول.

## لوحة تنزيل موحدة وإشعارات الإنجاز

تجمع بطاقة الإضافة النوع والوجهة والجودة في شريط واحد متجاوب: Video أو Audio only أو ملف مباشر أو Torrent/Magnet، مع وجهة الكمبيوتر/الهاتف. يفتح محدد الجودة قائمة من «أفضل جودة» ثم `240p` حتى `8K`، ويتيح محدد الصوت `MP3` أو `M4A`. زيدت أحجام الخطوط الثانوية وتباينها في لوحة التحكم وشاشة الاقتران.

عند اكتمال التنزيل تظهر رسالة Toast مؤقتة لمدة 15 ثانية. في نسخة سطح المكتب تتضمن اختصار فتح الملف أو إظهار مجلده، مع إخفاء خيار فتح الملف المفرد للتورنت؛ وتظل مسارات الملفات داخل تحقق Electron ولا تُعرض في Relay API.

## GitHub Auto-Updater

ملف البناء مرتبط صراحةً بمستودع GitHub العام `sam3sam323-afk/levelup`. في النسخة المعبأة يفحص `electron-updater` التحديثات، ينزّل الإصدار المتاح ويعرض الحالة، ثم يثبت التحديث عند إعادة التشغيل. لا يوجد `GH_TOKEN` داخل التطبيق أو ملفات الإعداد. نشر Release وتوليد ملفات التحديث عملية منفصلة تحتاج اعتماد GitHub خارج التطبيق؛ لم يضمّن أمر بناء v1.1.0 نشر Release.

## اختبارات التكامل المحلية

```bash
pnpm check
pnpm lint
pnpm test
pnpm binaries:verify
pnpm binaries:smoke:win
YTDLP_PATH=/path/to/yt-dlp ARIA2C_PATH=/path/to/aria2c FFMPEG_PATH=/path/to/ffmpeg pnpm relay:e2e
```

`binaries:smoke:win` يشغّل ملفات Windows الحقيقية (عبر Wine على Linux) على ملف مباشر ووسيط Matroska محليين، ثم يتحقق من بايتات التنزيل وملف MP4. `relay:e2e` يبدأ الخادم على منفذ مؤقت ويرسل طلبات API للهاتف والكمبيوتر باستخدام fixtures محلية مولدة؛ لا يتصل الاختبار بأي منصة فيديو أو خادم خارجي.

## تشغيل Electron أثناء التطوير

```bash
pnpm binaries:fetch
pnpm desktop:run
```

يفتح Electron لوحة الكمبيوتر على `http://localhost:8787` ويدير خادم Relay داخل عملية التطبيق. إذا لم تُجهز ملفات Windows الثنائية، يمكن تشغيل المصدر على الأنظمة الأخرى باستخدام `yt-dlp` و`FFmpeg` و`aria2c` من `PATH` أو تمرير المسارات عبر متغيرات البيئة.

## ربط الهاتف عبر Wi‑Fi

شغّل تطبيق Expo في وضع التطوير على الهاتف عبر `pnpm dev:metro`، ثم افتح المشروع بواسطة Expo Go أو بناء Expo متوافق. في تطبيق الكمبيوتر افتح لوحة Relay على `http://localhost:8787`؛ يعرض العنوان المحلي وQR ورمزًا من ستة أرقام. امسح QR من شاشة الاقتران أو أدخل العنوان والرمز يدويًا. الرمز مؤقت ويُستخدم مرة واحدة.

يستقبل Relay طلب `POST` محميًا ويقرر توجيهه إلى الكمبيوتر أو الهاتف. تنزيل الكمبيوتر يستخدم المحركات على الجهاز نفسه؛ تنزيل الهاتف المباشر يقبل HTTP/HTTPS ويحفظ الملف داخل مساحة التطبيق على الهاتف. أحداث تنزيلات الكمبيوتر تصل إلى اللوحة عبر SSE، ويحدّث تطبيق الهاتف حالته كل نحو 1.3 ثانية.

تأكد من اتصال الجهازين بالشبكة نفسها، واسمح باتصال TCP `8787` على الشبكة الخاصة عند ظهور طلب جدار الحماية. لا تعرّض المنفذ إلى الإنترنت العام. حركة Relay المحلية HTTP غير مشفرة؛ استخدمها ضمن شبكة موثوقة. اختيار الهاتف لا يحوّل روابط الفيديو أو التورنت إلى تنزيل هاتف مباشر؛ هذه الأنواع توجه إلى الكمبيوتر.

يمنع Relay وجهات Loopback وLink-local وMulticast وبعض العناوين المحجوزة بعد حل اسم المضيف، ويسمح بعناوين LAN الخاصة عمدًا للملفات المحلية وNAS. هذا الفحص يتحقق من الوجهة الأولية فقط؛ لا يعيد فحص التحويلات التي يتبعها المحرك أو أي تغيير DNS لاحق، لذلك لا ترسل روابط غير موثوقة ولا تكشف منفذ Relay للإنترنت.

## المحركات الحقيقية

للفيديو، يستدعي `yt-dlp` المصدر المحدد ويختار الجودة المطابقة أولًا من `240p` وحتى `8K` (تُحوّل 4K إلى 2160 و8K إلى 4320)، ثم يستخدم أقرب جودة متاحة لا تتجاوز الحد المختار. يدمج الصوت والصورة ويعيد تغليف الملف MP4 باستخدام `FFmpeg` متى سمح المصدر والصيغ المتاحة.

للصوت فقط، يستدعي `yt-dlp` مع `FFmpeg` لإنتاج MP3 أو M4A. للملفات المباشرة وZIP وAPK وEXE والتورنت وروابط Magnet، يستدعي `aria2c` مع `16` اتصالًا وتقسيمًا متعددًا و`16` نظيرًا لـBitTorrent. تبث المحركات النسبة والسرعة وETA إلى Relay، وتعرضها اللوحة، ويمكن إلغاء المهام. تُحفظ ملفات الكمبيوتر افتراضيًا في `~/Downloads/LEVEL-UP-ARENA-NEXUS`، وتظهر في مكتبة التطبيق.

تظهر حالة المحركات في اللوحة. أثناء التشغيل من المصدر يمكن تحديد المسارات بهذه المتغيرات: `YTDLP_PATH` و`FFMPEG_PATH` و`ARIA2C_PATH`. استخدم `NEXUS_DOWNLOAD_DIR` لتغيير مجلد الملفات، و`NEXUS_PORT` لتغيير منفذ Relay (الافتراضي `8787`)، و`NEXUS_RELAY_IP` لتحديد عنوان IPv4 خاص يدويًا. يستمع Relay على `0.0.0.0` حتى يمكن للهاتف الوصول عبر الشبكة المحلية.

## الأيقونة والتراخيص

الصورة الرسمية المعتمدة مستخدمة في `assets/images/nexus-official.png`، ونسختها متعددة الأحجام في `assets/images/icon.ico`. يستخدم Electron هذه النسخة في نافذة وشريط مهام Windows، ويستخدمها electron-builder لأيقونة البرنامج وملفات Setup وإزالة التثبيت. تبقى الصورة المصدر المرفقة محفوظة دون تعديل.

## حدود التحقق

فحوص TypeScript والاختبارات واستخراج حالة المحركات وAPI يمكن تنفيذها داخل Sandbox. ويمكن تشغيل ملفات Windows المضمّنة واختبار اتصال HTTP محلي عبر Wine، لكن لا يتوفر هنا كمبيوتر Windows فعلي أو هاتف على شبكة Wi‑Fi مشتركة أو كاميرا هاتف؛ يلزم اختبار تثبيت Setup والاقتران بالـQR على جهازين حقيقيين قبل اعتبارهما مجرّبين ميدانيًا. اختبار Auto-Updater end-to-end يتطلب GitHub Release منشورًا بالإصدار وملفات `latest.yml`؛ لم يُنشر Release ضمن هذا التنفيذ. مثبت Windows غير موقّع رقميًا، لذلك قد يعرض SmartScreen تنبيهًا عند التثبيت.
